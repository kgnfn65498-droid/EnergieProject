# v32.4.55 Autonomous Release Recovery Implementation Plan

> **For agentic workers:** execute task-by-task with TDD RED→GREEN.

**Goal:** Make canonical release ingress self-healing for duplicate Incoming, corrupt stable ZIP, orphan Processing and stale installer locks.

**Architecture:** A focused Python helper owns classification/recovery decisions and machine-readable evidence. `release_watcher.sh` invokes it before normal ingress processing; `release_installer.sh` writes installer lock ownership/heartbeat evidence. Existing atomic/mode gates remain the outer safety fence.

**Tech Stack:** Python 3.12, POSIX sh, pytest.

**Spec:** `docs/superpowers/specs/2026-09-15-v32.4.55-autonomous-release-recovery-design.md`

## Global Constraints
- Canonical route remains ZIP → Incoming → watcher → installer → live → acceptance → processed.
- No arbitrary shell rescue action.
- No active lock stealing.
- No production write during build/test.
- TDD RED→GREEN.
