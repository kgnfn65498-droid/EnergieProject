# v32.4.55 Autonomous Release Recovery Design

**Approved basis:** `Data/03_Systeem/Projectmanager/Requirements/HARD_REQUIREMENT_32455_AUTONOMOUS_RELEASE_RECOVERY_NO_TERMINAL.md` plus Peter's instruction on 2026-09-15 to minimize Codex and deliver one self-audited candidate ZIP.

## Goal
Make the canonical ZIP → Incoming → watcher → installer path self-healing for the proven release-ingress failures without adding an alternate deployment path or arbitrary shell executor.

## Scope
1. Add one bounded release-ingress recovery helper used by the watcher.
2. Exact duplicate Incoming ZIPs are canonicalized safely; different ZIP contents remain fail-closed.
3. Stable corrupt ZIPs are quarantined instead of waiting forever.
4. Orphan Processing is returned to Incoming only when installer ownership is proven absent/stale and the item is old enough.
5. Installer lock gains owner + heartbeat evidence; active locks are never stolen, stale locks may be recovered only under strict age/evidence rules.
6. Existing half-written ZIP stabilization, atomic ingress gate and watcher heartbeat semantics remain unchanged.
7. Existing FINAL Projectmanager provenance checks remain authoritative; no bypass.
8. Release identity becomes 32.4.55 and the candidate is built only after targeted and full regression.

## Safety rules
- Never pick arbitrarily between different Incoming releases.
- Never remove an active installer lock.
- Never recover Processing while fresh installer evidence exists.
- Never bypass LIVE_ACCEPTANCE/atomic ingress gates.
- No production writes from the build/audit environment.
- All recovery actions are idempotent and produce machine-readable evidence under Inbox/logs.

## Acceptance
- Duplicate identical Incoming converges to exactly one canonical ZIP.
- Different Incoming contents remain unchanged and BLOCKED.
- Half-written ZIP never gets quarantined before stability threshold.
- Stable corrupt ZIP is moved to failed/corrupt and no install starts.
- Crash after Incoming→Processing self-recovers after stale threshold.
- Stale installer lock without live heartbeat can be recovered; fresh lock is preserved.
- Watcher restart repeats recovery without duplicate side effects.
- Existing watcher lock, atomic gate, hold and transition tests remain GREEN.
- Full regression, compile, shell syntax, manifest, ZIP CRC and fresh-extract verification are GREEN before Codex receives the artifact.
