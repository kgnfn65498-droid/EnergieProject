# v32.3.18 Live Mode GUI Refresh Design

## Goal
After any GUI operating-mode or release-hold action, the Home Assistant Ingress page must immediately show the newly measured operating-mode state without requiring a manual browser refresh.

## Scope
- Keep all existing mode, RELEASE VALIDATION HOLD, reconciliation, Crash Recovery, watcher, scheduler and month-close semantics unchanged.
- Intercept only the operating-mode card GUI forms that already opt in with `return_ui=1`.
- Submit those forms with same-origin `fetch`, preserve the existing POST endpoint and safety checks, follow the existing 303 PRG redirect, and then navigate to the returned redirected URL so the browser renders a fresh server-side status snapshot.
- Preserve the existing non-GUI JSON API contract unchanged.
- Preserve Ingress-relative routing and fixed notice codes.
- Correct the existing misleading release-hold notice mapping: a blocked hold validation must render a fixed error notice and must never be labelled `Reconcile OK`.
- On any fetch/network failure, fall back to a full page reload; do not guess success.

## Acceptance criteria
1. USER/DEVELOPMENT/MAINTENANCE, automatic switching, reconcile, normal hold validation and emergency hold release all use the fresh-navigation path.
2. The redirected page immediately contains the new measured status and fixed notice banner; manual refresh is not required.
3. A blocked release-hold validation produces `release_hold_blocked` with error level.
4. Non-GUI callers still receive JSON exactly as before.
5. No operating-mode safety semantics change.
6. Existing v32.3.17 publication fix remains untouched.
7. Full regression suite and definitive ZIP tests pass before delivery.
8. After the definitive ZIP is green, review Crash Recovery scripts and mode-session integration for conflicts before live Crash Recovery use.

## Release exit
When v32.3.18 passes live GUI refresh validation, `MODES_EXIT = PASS` for the current operating-mode scope.
