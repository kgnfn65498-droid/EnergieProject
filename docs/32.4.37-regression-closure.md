# 32.4.37 regressieclosure

## Scope
Pure closure van 32.4.36. Geen ngrok-, Voice-, handover- of 32.5-functionaliteit.

## Defect 1 — watcher upgradegrens
**Symptoom:** nieuwe watcher-code draait na upgrade in de oude containerconfig en kan daardoor de nieuwe Docker-socket/hardening missen.
**Root cause:** `exec` vervangt een proces, niet Docker mounts/capabilities.
**Fix:** containercontract v2 + fail-closed capabilityprobe. Drift wordt `RECREATE_REQUIRED`; geen schijn-GREEN. De eerste overgang vanuit een reeds draaiende 4.36-container zonder socket vereist bij live acceptance één beschermde externe containerrecreate.
**Preventie:** iedere toekomstige watcher-infrastructuurwijziging wijzigt en verifieert het containercontract.

## Defect 2 — native MCP bron/runtime drift
**Symptoom:** hotfix op disk kan groen zijn terwijl het draaiende Pythonproces oude modules heeft geladen.
**Root cause:** modulecode wordt niet automatisch herladen.
**Fix:** deterministische bronfingerprint, runtime-marker bij import en een Peter-goedgekeurde fixed-target restart van uitsluitend `energie-filesystem-mcp`.
**Preventie:** bron/runtime mismatch blijft `RELOAD_REQUIRED`; CR acceptance mag dan niet groen worden verklaard.

## Defect 3 — CR retentiecommit
**Symptoom:** directe file-by-file delete kon bij een halverwege mislukte commit niet volledig worden teruggedraaid.
**Root cause:** destructieve commit was niet transactioneel.
**Fix:** oude volledige geldige sets eerst atomisch naar `Backups/CRRetentionQuarantine/<type>` verplaatsen met oorsprongmanifest; geen delete in de retentiecommit.
**Preventie:** tests bewijzen rollback bij commitfouten en max-1 pas na volledige nieuwe-setvalidatie.

## Defect 4 — post-release status/mode
**Symptoom:** een startup-RED kon later door `WATCHER_ACTIVE` worden gemaskeerd; een reeds toegepaste MAINTENANCE-marker kon opnieuw de modus terugzetten.
**Fix:** geaggregeerde startup-degradation + eenmalige/idempotente post-release marker.

## CLEARUP
Geen scopewijziging: oude plannen worden geweigerd, daarna exact één verse dependency/reference-audit. Alleen hard move naar CLEARUP, bronpad moet verdwijnen, herkomst/restore wordt vastgelegd, symlink/live references blijven blokkerend, delete blijft uitgeschakeld.
